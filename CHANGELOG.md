## [Unreleased]

### Added
- **A run reports which whitelist words it left behind.** A user mining a fixed word list (Settings → Filtering → Whitelist, with the frequency cutoff set low so nothing else survives) could see the cards it made but not the words it never found — "it won't tell me which words in the whitelist it couldn't find. That's the only feature missing doing it this way". The receipt line every mining screen already ends on now carries `· Whitelist: 14 of 20 mined`, a **Copy unmined words** button puts the leftovers on the clipboard one per line — ready to be the next whitelist file — and the Activity Log gets one run-level line naming them, with words that were already in Anki or on the known-words list called out separately so nobody hunts for a sentence they already have. The report is run-level on purpose: over a twelve-episode batch a word absent from episode one is usually mined by episode five, so a per-item line would report misses the run went on to fill. Mechanically, phase 2 snapshots the whitelist against the parse *after* the known-vocabulary subtraction and *before* the offline-definition filter — an entry dropped for having no dictionary entry must not be misfiled as already known — and the result carries a small frozen `WhitelistCoverage` that the run receipt folds with a union in which mined outranks known, since a word this run carded in episode one comes back as "already in Anki" when episode two looks. The mined half is stamped at `_run_pipeline`'s result funnel beside the write-provenance stamp rather than at the end of phase 5, because a cancelled result is built outside `build_result` and a run that dies after AnkiConnect confirmed a batch never reaches phase 5's tail; it reads Anki's own confirmation lists, which `_reset_run_write_state` now clears per run so a shared Batch service cannot attribute the previous item's cards to an item that never got as far as Anki. The Batch queue worker, which reports counts rather than results, folds its own coverage over its pairs (both the per-pair path and season mode's pre-pass and mine pass) and hands it over on `queue_finished`. The log line is written to the screen's own Activity Log rather than through the presenter, because only Video → Single and Video → Batch route presenter messages there; the queue screens send them to the window's transient status bar, where a report you came back for would already be gone. "Not mined" is the honest label: a word dropped for having no dictionary entry, deselected in the Word Curator, or refused by Anki as a duplicate is listed as not mined without a guess at why, and the existing per-run warnings already name those cases. Deck Builder is untouched — its bypass of the optional filters is part of the whitelist gate. No new setting.
- **Secondary-language subtitles (Video → Single, behind Settings → Filtering → Secondary Subtitles).** Off by default. With it on, the tab grows a Translation Subtitles picker and a Translation Offset spin; the second track's line is drawn under the mining-language cue in the Word Curator preview, appears as a hideable Translation column, and is written to a new optional Translation field (Cards & Anki → Translation Field; the Kiku and Senren presets map their existing `SentenceTranslation` / `sentenceTranslation`). Matching is a time-overlap join, not a line-index one: every secondary cue overlapping a word's sentence window by at least 0.2 s attaches, in time order, so one primary line spanning two translated ones keeps both, and an edge touch between neighbouring lines attaches nothing. The second track is parsed once at a zero offset and its own offset is applied at match time, which is what lets the curator hold the same cues and repaint the column live as a sentence is picked or a line is added — the processor then runs the identical rule after curation and expansion materialisation, so the card agrees with the column by construction. The preview strip follows the D45-B contract (cleared between cues, never hidden per cue; visibility decided once per source). The field rides the always-emitted `field_data` map, since `OPTIONAL_FIELD_KEYS` is frozen. Batch and Reading → Subtitles are not covered: batch pairing is episode-number-only across two folders, and reading subtitle units carry no cue times. The secondary offset is per run and remembered with the recent file pair, not a setting. The second file is decoded on its own terms: a UTF-8 or UTF-16 file reads as itself, and any other encoding goes through charset detection rather than the mining language's own ladder, because the second file is not in that language (cp932 would otherwise swallow a cp1252 curly apostrophe as one double-byte character); a file that cannot be decoded fails the run naming the file. The mining language's line cleaning and the subtitle regex filter still run on the second track.
- **A whole folder can condense into one file (Utilities → Condense, folder mode).** A season of episodes becomes a single track — one anime season, one mp3 — with an optional output name that defaults to the source folder's. Each episode still condenses through the unchanged single-pass `aselect` path, but into a private staging folder under `media_temp_folder`; the parts are then joined with ffmpeg's concat demuxer and `-c copy`, so nothing is re-encoded. Stream copy needs identical stream parameters and `_encoder_settings` pins only codec and bitrate, so a merge run additionally pins each part to 48 kHz stereo (`uniform_layout`) — a normal run keeps the source's own rate and layout, byte-identical to before. FLAC is the one format that is re-encoded rather than copied: a native `.flac` carries its own header and STREAMINFO per file, so copied parts restart the timeline and the merged file reports the first part's duration while holding every part's bytes; re-encoding costs nothing audible because flac is lossless. The merged `.srt`/`.lrc` sidecar shifts each episode's condensed cues by the *probed* length of the parts before it rather than the summed interval arithmetic: encoder delay and whole-frame padding make a written part tens of milliseconds longer than its intervals, which would put the end of a long season about a second out of sync. A failed episode reports its own error and the merge proceeds over what succeeded; a cancel, a fatal encoder error or a run where every file failed writes nothing, and the staging folder is removed on every exit path. The merge is emitted as one more queue item, so the progress bar, the Activity surfaces and the terminal outcome need no new signal contract. An existing merged file is refused up front unless Overwrite is ticked, since a merge run that skipped its only output would otherwise report success and write nothing.
- **Screenshot frame selection (Word Curator).** A card's screenshot was always grabbed `screenshot_offset` seconds after the subtitle line starts, so a transition, a fade or a black frame could only be dodged by moving a global setting that then missed on every other card. Two buttons under the preview player — *Use current frame* and *Reset frame* — stamp the instant the player is showing onto that one word, or put it back to the computed default. The pick rides the same per-word channel `clip_override` and `line_expansion` already use: `TokenizedWord.screenshot_override` carries absolute seconds on the source video's own timeline, and `media_extractor.resolve_screenshot_time` is the only place it is read, mirroring `resolve_audio_window`. Picking a different sentence drops the frame (it was chosen while looking at another scene); merging a neighbouring line keeps it (the same scene, extended). The buttons are absent where there is no frame to grab — animated screenshots, a preview-disabled or audio-only player, and the reading and manga curators — and disabled while season curation is still swapping the player to the focused word's episode. An untouched word extracts exactly as it did before.
- **The Word Curator's columns can be reordered, hidden and are remembered.** Drag a header section to move a column; right-click the header for a checkable menu of every column plus **Reset columns**, the recovery path for an arrangement the user cannot undo by hand — a hidden column has no section left to right-click. The include column is deliberately absent from that menu: it carries the row's check state and its original-word index, so hiding it would leave the dialog with no way to include or exclude a word. Indices stay logical, so neither a move nor a hide touches the cell writes. The arrangement is a `QHeaderView.saveState()` blob in `ui_state.ini` (`curator/columns`), keyed by the column count — `restoreState` does not refuse a blob whose section count no longer matches, it applies what it can and leaves columns hidden or misordered, which reads as a lost column rather than as stale state, so a count mismatch means "compute the default". Resize modes are re-pinned after every restore, because the blob carries them and an older arrangement could otherwise pin `Stretch` onto the wrong column.
- **Two sentence-signal columns in the Word Curator: Unknowns in line and Sentence length.** The first counts how many words on the word's own subtitle line this run does not consider known — sort ascending and the i+1 lines come first, the ones whose only unknown word is this one. The second is the character count of the example sentence; sort ascending for the shortest. Both are columns rather than filters on purpose: the i+1 and sentence-length filters answer the same two questions by dropping words, and sorting keeps every word minable. Both sort numerically and both move with the picked sentence variant, so switching a word's sentence updates them in place. An uncomputed count prints `-` and sorts last, exactly like an unranked frequency rank, rather than sorting above every real count as a `0` would.
- **`K` adds the highlighted rows to Known Words (Word Curator).** The same verb as the **Add to Known Words** button, which already decides the direction and no-ops without a commit callback. The shortcut is table-scoped like the rest of the dialog's keys: a window-scoped `K` would stage words while the user is typing into Search.
- **A YouTube run picks where its subtitles come from (Video → YouTube → Subtitles).** The reported workflow was Utilities → Download, then Utilities → Generate for subtitles, then Video → Single to mine, because "the automatic subtitles from YouTube are wrong or not even in sync 99% of the time". Both halves of that now happen inside the one run. A per-run picker offers **Auto** (manual captions, then native auto-captions, then local transcription), **Always transcribe** (ignore YouTube's captions and run Whisper on the download) and **Captions only** (the previous behaviour, refusal included). The choice is a `SubtitleSource`, deliberately a separate type from the per-video `SubMode` it resolves to: intent over the queue versus the route one video got. In transcribe mode the fetcher emits no `--write-sub`/`--write-auto-sub`/`--sub-lang` flags and `_resolve_outputs` returns `subtitle_file=None` instead of raising, while keeping every video check — a truncated download must never reach the ASR pass; `process_youtube_url` then fills the hole with the same `generate_subtitle_one` the Generate tab uses, writing into the worker-owned workspace the existing `rmtree` already covers, before `on_fetched`, so the curator preview still gets a real SRT. Progress rides the fetch callback that was already wired, because ASR is the longest stage in a run and must not look hung. Because a probe runs at Add time while the picker is a run-time control, changing it re-decides every already-probed row offline from its stored `VideoInfo` — a video refused for having no captions recovers without a second network round trip — and that sweep is refused mid-run, since the worker reads `resolved_sub_mode` off unclaimed READY rows. Two latent bugs on the reject path were fixed to make it sound: `video_id` was only ever written on the accept path (a promoted row would have tripped `_mine_one`'s completeness guard) and `resolved_sub_mode` was never cleared (a demoted row kept a stale mode the retry path reads).
- **Fetched captions can be retimed against the video's audio before mining (Video → YouTube → Align captions to audio).** Off by default, and the answer to the "not even in sync" half of the same report. It reuses `retime_subtitle` whole — the four-engine ffsubsync/alass chain, the dialogue-only cleaning and the result validation — so a failure is a falsy `RetimeOutcome` with the original file untouched and the run continues on the captions it already had. Skipped for a locally transcribed track, which came from that audio to begin with. The retimed track is written as a workspace sibling rather than over the original, because `retime_subtitle` keeps no copy when told to overwrite in place.
- **A transcription run is refused before the first download when no ASR model is installed.** Two layers, both gated on the queue actually containing a `transcribe` row so a captions-only run is never blocked: the tab shows a screen-issue banner from `_start_run` (its single choke point, so Mine, Retry selected and Reset-and-run all pass through) with a route to Settings, and a new `_asr_preflight_message` hook on `SequentialQueueWorker` aborts the queue off the GUI thread for every other entry point. The hook defaults to `None`, unlike the abstract `_stale_reimport_message` beside it, so the other four queues are untouched. `SubtitleCreationTab._any_usable_model_installed` moved out to `services/asr/model_availability.usable_model_installed` so both gates reach the same verdict; it cannot live in `model_manager` without an import cycle. Without it the failure was a raw ctranslate2 exception after a full download per row.

### Changed
- **The log now answers a bug report on its own.** Eight motivating reports had a log that could not say what the app had been doing: an expression-audio run that stalled with no pack folder named, a YouTube fetch whose every line read `https://www.youtube.com/watch`, a native crash whose only trace was a file the report never mentioned. Every record now carries milliseconds and the producing thread's name (`%(asctime)s.%(msecs)03d %(levelname)-8s [%(threadName)s] %(name)s:%(lineno)d`), and the threads have names worth printing — `CancellableWorker.log_start` renames each worker to its run context and the GUI thread is `main`, replacing the old `Dummy-N`. The ring doubled to 16 MiB × 5 backups (~96 MiB worst case), because at 8 MiB a high-coverage batch could overwrite the session boundary before anyone read it. What gets written grew with it: a session start and end pairing on one id, the effective configuration, the resource and store inventories, every run and task lifecycle transition, queue items and retries, curator decisions, off-thread dispatches, window-close joins, every external process's argv and stderr tail, which binary each resolver picked and why a tier was refused, yt-dlp's cookie source, capabilities and error classification, pipeline phases, definition batches, per-source audio outcomes, subtitle decode decisions, index and slot rejections, import row counts, and the health checks. Unhandled exceptions in threads, unraisable exceptions, Qt's own messages and Python warnings are captured too, so a failure outside our call stack still lands in the file. Paths, mined words, deck names, video ids and exception messages are logged verbatim, reversing an earlier redaction rule that had removed exactly the evidence support requests were asking for; secrets stay masked — URL userinfo, credential argv values, custom-audio query strings and cookie contents. `suppressed()` replaced the silent `except Exception: pass` handlers, and a per-file budget ratchets the remainder down instead of letting new ones in. The whole overhaul adds no setting: the project's own DEBUG lines are always on disk, and `ANKI_MINER_LOG_LEVEL` lowers only the root level when third-party chatter is wanted. Help → Export Diagnostics… keeps pace at `bundle_format: 2`, adding the on-disk config and state files (`gui_config*`, `ui_state.ini`, profiles, queue snapshots, download manifests) and the resource, store, disk and screen inventories to the logs, environment, health and settings members it already carried; `CONTRIBUTING.md` → Logging records the contract.
- **Inline run options are remembered between launches.** "Review words before mining" reset to off on every restart on all seven screens that offer it, which a user reported as forgetting to tick it every time; the sweep that followed found the same gap across the rest of the per-run controls. Now persisted into `gui_config.json`, so they also travel with a settings profile and an export: the curation checkbox (one shared preference — ticking it on Video → Batch ticks it on YouTube, Audiobook and all four Reading screens, because whether you approve words before cards are made is one decision, not seven), YouTube's caption source and Align captions, Deck Builder's word-selection mode with its Top N / coverage value and Skip-known, and Card Backfill's field groups. The mechanism is the one Condense and Download already used — the screen folds its edit into a fresh config with `dataclasses.replace` and emits a signal the window saves — factored into a `RunOptionsMixin` whose re-entrant seed guard is what stops a save from looping back through `config_refreshed` into another save. The signal is connected by capability discovery in `compose_main_window` rather than a hand-kept list, since these screens sit up to three levels deep inside container tabs. Card Backfill needed one extra rule: its two gates un-tick a group whose Anki fields are unmapped or whose mining language lacks the capability, so config stores the user's intent and the widget shows the gated view — a masked group keeps its stored value instead of contributing its gate-forced widget state, or toggling any other group would erase it. Four things are deliberately left transient: the "Overwrite existing…" checkboxes on Condense, Generate, Retime and Card Backfill (off-by-default each launch is a safety property — a tick in March must not still be armed in June with no reminder, and this is now pinned by a test rather than left to look like an oversight), and the per-session subtitle-offset spinboxes, which describe one video rather than a preference.
- **A YouTube video with no captions is now mined by transcribing it, instead of being refused when it is added.** This is the default (`Auto`) behaviour and the one behaviour change in the picker: such a video used to fail its probe with "No Japanese subtitles available for this video." and could never be queued. The cost is visible rather than silent — the row reads "Transcribed locally", the progress line reads "Transcribing · N%" — and the run is refused up front if no model is installed. Choose **Captions only** for byte-identical previous behaviour.
- **Release assets all carry the version.** The two macOS tarballs shipped as `AnkiMiner-macOS-arm64.tar.gz` / `AnkiMiner-macOS-x86_64.tar.gz` — the only assets on the Releases page without a version, since the AppImage, the Windows installer and the `.deb` all had one. They are now `AnkiMiner-<version>-macOS-<arch>.tar.gz`, and every non-`.deb` asset path in `release.yml` is built from a single `AnkiMiner-{version}-{asset_slug}` template driven by a new `asset_slug` field in `.github/release-matrix.json`. The `.deb` keeps Debian's mandated `anki-miner_<version>_amd64.deb` shape, which `dpkg-name` and apt repos assume, and is the documented exception. The in-app updater matched the old macOS names as exact literals and now matches every target by a version-agnostic glob, so a future rename cannot silently degrade the update banner again; `tests/unit/test_release_asset_names.py` pins the scheme against all five producers — `release.yml`, `release-matrix.json`, `build-appimage.sh`, `anki_miner.iss` and `nfpm.yaml` — and asserts each published name is claimed by exactly one updater target. Existing macOS installs get a release-page link instead of a direct download for the one upgrade that crosses the rename. CI artifact names are deliberately unchanged: `scripts/artifact_size_baseline.json` is keyed on them.

### Fixed
- **A failing audio fetch names the word, and a failing YouTube fetch names the video.** Both had been redacted into uselessness. Expression audio counted its failures and logged an identity digest instead of the word, so a user whose run stalled on one pack could not be told which entry it was stuck on; every source now reports through one `log_fetch_outcome` choke point carrying the mined form, the reading, the URL, the HTTP status or body problem, and a stable reason — rate-limited per source and reason so a whole-episode outage is a handful of lines rather than one per word. yt-dlp lines went through a redactor that dropped the entire query string, which for YouTube is the video id, leaving every record about every video byte-identical; the id, playlist, index and timestamp are kept now and only tracking parameters are dropped.
- **A failed YouTube download names the reason instead of listing download byte counts.** `--progress-template` emits one line per progress tick, and both yt-dlp services appended every line to the 50-entry deque they keep for the failure message — on a real 8-minute fetch that is 45 progress lines out of 60, so the extraction phase was evicted before the process even exited and the raised error carried twenty lines of `[ankimine_dl] <downloaded> <total>`. The same tail feeds `classify_error_tail`, so once a download had started none of the typed remedies could match any more: a bot wall, a locked or undecryptable cookie source and a stale extractor all degraded to a generic `YouTubeFetchError` carrying the byte counts. That also cost a full re-download per attempt, since those classified subclasses are exactly the ones `_DETERMINISTIC_FETCH_ERRORS` keeps out of the queue worker's retry — a reporter's log showed one video fetched three times across four minutes for a deterministic failure, with nothing in the log to say what the failure was. Progress lines are now kept out of the tail by a shared `is_progress_only` predicate, which still retains a line yt-dlp flushed a warning onto alongside a progress record. Utilities → Download carried the identical defect and takes the same fix.
- **Korean 하다-predicates mine as their dictionary form.** kiwipiepy splits 공부하고 into 공부/NNG + 하/XSV, and `XS` is not a mineable tag, so the card front was the bare noun 공부 — and 깨끗한 mined the bound root 깨끗, which no dictionary lists. An attached nominal plus an `XSV`/`XSA` suffix now merge into one predicate token whose lemma is noun + suffix + 다, gated on that form being an exact offline-dictionary headword, through a new `token_merger` seam on `SubtitleParserService` run with the memoised `offline_terms_exist` probe the compound matcher already uses. Japanese and Chinese pass nothing into that seam, so their output is byte-identical. A free-standing or whitespace-separated 하다 is tagged `VV`, never `XSV`, so 공부를 했어요 and a bare 공부 시간 still mine the noun.
- **A run that mines no words names the cause instead of reporting "No words found".** The first Chinese YouTube report was undiagnosable: every zero-word outcome logged only `tokens=0`, and the three routes that produce one all said the same thing. Each zero-word parse now writes one WARNING naming the mining language, the tagger's own language, the POS whitelist and the raw tag counts — every zero-word Chinese outcome turns out to be the POS gate rejecting all tags. The parser refuses to tokenize a config whose language has degraded to Japanese, with a `SetupError` naming the language (raw-entry previews are unaffected); `process_episode` and `process_reading` report "Subtitles contain no <language> text" when no line carries the mining script; and the YouTube probe's rejection names the profile's language instead of hardcoding "Japanese".

## [3.0.0] - 2026-09-02

### Added
- **Chinese and Korean mining (Settings → Mining Language).** The app mines three languages now, and the selector switches between them without a restart. Chinese runs on jieba for segmentation, pypinyin for readings and OpenCC for script variants, and adds four things Japanese has no use for: a Character Set choice (Simplified 简体 / Traditional 繁體) that steers both the card front and the dictionary lookup, tone-coloured pinyin (each syllable wrapped in a tone class the card styling paints), a Measure Word field taking the classifier off the dictionary entry, and a Traditional field carrying the other spelling when it differs. Korean runs on kiwipiepy with Sejong part-of-speech defaults, adds a Hanja field for the Chinese characters inside a word and two script filters (Hangul-only, contains hanja), and splits reading sentences on its own punctuation rules. Each language brings its own deck default, dictionary catalogue, audio ladder, subtitle decode ladder, sentence rules and mined-form policy; OpenCC is optional, and its absence costs script variants only.
- **Switching mining language moves the whole configuration with it.** The switch runs behind the same mutation guard a dictionary import takes, so it refuses while resources are busy rather than pulling a database out from under a live lookup, and it refuses outright while mining is running. Queued work is not silently discarded: a switch with rows in a queue asks first and flushes only on confirmation. Everything language-scoped — deck, card fields, dictionary and frequency chains, filters, script settings — is parked in `config.language_stash` on the way out and restored on the way back, so a round trip lands exactly where it left. A settings-profile switch whose snapshot names another language takes the same path rather than a shortcut. On the first visit to a language, the app offers to exclude the decks belonging to the others and to open the Setup Wizard.
- **Downloadable language packs (Settings → Mining Language).** The frozen bundle ships neither the Chinese nor the Korean engine: both arrive as sha256-pinned PyPI artifacts declared in per-language manifests, downloaded on demand into `~/.anki_miner/language_packs/` and appended to the import path at boot, through the same staged install path the ASR models and alass use. A language whose engine is missing is not in the selector at all, and the download row under Mining Language is the one place on screen that explains where it went — reinforced by a boot banner that opens Settings on the selector when the active language's pack is absent. Korean's pack carries the ~88 MB model alongside the engine; a pre-existing `ko_model/` from an earlier build is honoured read-only, so nobody re-downloads it. A pip install with the `[zh]` or `[ko]` extra already has everything from PyPI and never sees the rows do anything.
- **A recommended Korean dictionary (Setup Wizard, and Settings → Dictionaries).** KRDICT — 국립국어원's 한국어기초사전 — is offered for download the way JMdict is for Japanese and CC-CEDICT is for Chinese, so Korean no longer starts with an empty resource page. The licence was settled by reading the artifact rather than the repository hosting it: every build carries its own `index.json` attribution naming 국립국어원 and CC BY-SA 2.0 KR, which is the licence the institute has distributed 한국어기초사전, 표준국어대사전 and 우리말샘 under since 2019. The pinned build is the one without example sentences, because the sentences quoted from publications are the one part of the data the open licence does not cover. Attribution runs to 국립국어원; the Yomitan conversion is credited alongside it.
- **`scripts/convert_nikl_frequency.py` converts the NIKL Korean frequency survey into an importable CSV.** 국립국어원's 현대 국어 사용 빈도 조사 2 is KOGL Type 1 (출처표시) and therefore usable, but it ships as UTF-16 TSV inside a spreadsheet archive rather than as a Yomitan frequency meta-bank, so the source importer rejects it as downloaded. The script reads the archive's `일반어휘통계.txt` member and writes a direction-declared CSV of roughly 73,800 rows that imports like any other frequency source.
- **Cards can be created in order of appearance (Settings → Filtering → Card Order).** Off by default. With it on, the words handed to media extraction are re-sorted into the order they first appear in the episode, volume or document, so the notes AnkiConnect receives — and the new-card positions Anki assigns from them — form a clean series instead of a rough one. The sort runs after curation and is the last word on ordering, so it deliberately overrides the three things that reorder ahead of it: the whitelist's force-include prepend (which puts forced words first so they win the duplicate collapse), a column sort clicked in the Word Curator, and season mode's merged pool order. It covers every mining path that creates cards from a mined word list — single episode, batch, season, YouTube, audiobooks, the reading tabs and Deck Builder. Deck Filter, Card Backfill and Restyle are unaffected: none of them create cards from a word list.
- **WebVTT subtitles mine, pair and retime like the other formats.** `.vtt` joined the subtitle priority last, after `.ass`, `.ssa` and `.srt`, so it appears in the file picker's filter and in the drag-and-drop drop set without either being listed by hand. Utilities → Retime aligns one by transcoding to SRT first, since alass reads no VTT, and inline cue-timestamp tags are stripped out of the sentence rather than carried onto the card.
- **The mining language is reachable from Find a Feature.** The Usage Guide catalogue carries an entry for it, so searching for a language name lands on the selector.

### Changed
- **Every Japanese-specific mining decision now comes from a language profile.** `anki_miner/languages/` holds a `LanguageProfile` protocol, a registry, and one assembled profile per language; the Japanese profile is an adapter over the code that was already there, so `ja` behaves exactly as before. What used to be inlined is now dispatched through the profile: tokenizer access (a tagger provider, so nothing imports fugashi to mine Chinese), mined-form policy, dictionary key folding, definition-fallback strategy, script-type filtering, sentence splitting, the subtitle and known-words decode ladders, the expression-audio ladder, YouTube caption parameters, ASR language, audio-track matching, mined-content typography, and the render hooks that put furigana, pitch, pinyin or hanja on a card. Tokens crossing that boundary are duck-typed rather than fugashi objects.
- **Settings, Card Backfill and the readiness chrome show only what the active language has.** A profile declares capabilities (`pitch`, `furigana`, `kana_filters`, `name_wordsets` and `deinflection` for Japanese; `pinyin`, `tone_color`, `script_variants` and `measure_word` for Chinese; `hangul_filters` and `hanja` for Korean) and the surfaces derive from them: the pitch, furigana, kana-filter and name-wordset rows disappear under Chinese, the Character Set and tone-colour rows under Japanese, the Hanja row under both. The gate is two-way, so switching back re-shows the rows instead of hiding them until the next launch, and each row takes its own label with it. Card Backfill's field groups, the Setup Wizard's resource page (built from the language's catalogue, not a Japanese constant) and the first-run readiness banners follow the same source.
- **Known words, statistics, audio caches and imported resources are kept per language.** The known-words database and `stats.db` are partitioned by mining language, so a Chinese run neither reads nor writes the Japanese word list and Analytics counts one language at a time; the existing Japanese data keeps its current path. Every resource import is stamped with the language it was imported for, the stamp survives repair and Reimport All, and the chains skip slots indexed for another language rather than answering a lookup with them. Non-Japanese word-audio cache stems are namespaced by language so two languages cannot collide on one spelling.
- **The install extras carry the new engines, and the bundle carries none of them.** `pip install anki_miner[zh]` adds jieba, pypinyin and OpenCC; `[ko]` adds kiwipiepy and its model; `[languages]` takes both, and the default install stays as Japanese-lean as it was. The release smoke now runs a tokenizer leg per mining language against the built artifact, with each language's pack fetched first, since the bundle carries no engine. Dropping both took the Linux download from 970.6 MB to 925.6 MB and the Windows one from 286.5 MB to 266.6 MB. An artifact size report with a committed baseline runs on every release build, so the packs cannot grow the download unnoticed.
- **Mining Language is its own Settings page.** It used to be a row inside Filtering; it now sits in the side navigator beside the other destinations, carrying the language selector, the per-language pack download rows and the first-visit prompts.
- **Downloaded subtitles arrive as SRT (Utilities → Download).** The download tab and the YouTube fetcher used to ask yt-dlp for its VTT default and convert afterwards, which meant a subtitle-only download still needed ffmpeg on the machine to finish. Both request SRT directly now, and `--convert-subs` is gone.
- **The interface catalogues cover the Chinese and Korean surfaces.** The new mining rows, the language switch's own prompts and refusals, the language-pack download rows and boot banner, the audio-pack scan and import dialogs and the card-order strings are translated across all twelve shipped interface languages.
- **Deck Filter's drop-reason label reads "not the mining language" instead of "not Japanese"** (Utilities → Deck Filter), matching multi-language mining.

### Fixed
- **Subtitles in Big5, GB18030 and CP949 decode as themselves.** GB18030 maps every byte sequence, so it never fails and it swallowed Traditional Chinese subtitles whole, turning a Big5 file into a page of plausible-looking wrong characters instead of an error anything could catch; the ladder now decides between the two on the decoded text rather than on the first decoder that does not raise. Korean subtitles get CP949 in their ladder, and a subtitle whose byte-order mark was truncated by an earlier tool is read as UTF-8 again instead of falling through to a legacy codec.
- **A mining language with no usable engine degrades to Japanese instead of crashing.** A `gui_config.json` naming a language this build cannot supply — a hand-edited file, a settings profile from another install, or the `[zh]` extra simply not being present — used to raise out of every place that resolves the active profile, including the Setup Wizard's construction, the first-visit prompt and `AnkiService.__init__`, leaving no in-app way back. Every one of those sites now falls back to Japanese and logs once, and the moment the real profile registers the stored code is honoured again. A missing tokenizer package is reported as a language this build cannot mine, with the missing package named, rather than as an import error.
- **The Setup Wizard finishes for a language with no downloadable resources.** A language whose catalogue lists nothing — Korean's did until the KRDICT entry above, and any language's can, since a catalogue only holds what is both redistributable by link and shaped like the importers here — left the resource page offering an enabled Download button over a handler that returned silently, and gating Next on a dictionary probe that had nothing to find. The button is now derived from the selection rather than left enabled by default, an empty catalogue says where the resources are imported from instead, and Next stops waiting for a download that cannot happen.
- **Settings search no longer offers a setting the active language hides.** The index was built from every registered anchor, including the eight the language gate had already hidden, so typing "Character Set" on a Japanese configuration listed a row that scrolled to, focused and flashed a combo box that was not on screen. Visibility is resolved per anchor against its own panel — the index is built before Settings is ever shown, so a window-relative check would call every anchor invisible — and the index is rebuilt on a switch, since the gate moves rows. Every anchor stays addressable by id, so System Health's Fix deep links keep landing.
- **A language switch repaints everything it changed.** Mined-content typography was captured when a tab was built, so the outgoing language's letterforms survived until the next launch; Japanese block leading was applied to reading text in every language; a gated row hidden by one switch stayed hidden after switching back; and the audio chain's retry affordance was synced on some writes but not all. Frequency sources are probed with terms in their own language, the phase-2 script filter resolves through the profile actually held, and auto slot identity includes the language without forking the slots already on disk.
- **Media extraction hands its results back in the order it was given them.** The parallel ffmpeg pool harvested with `wait(FIRST_COMPLETED)` over a set and appended each finished word as it landed, so a long clip submitted first came back after several short ones submitted later. Phases 4 and 5 and `addNotes` are all strictly positional off that list, so completion order was the card order, and it varied run to run for the same episode. Results are now keyed by submission index and returned in input order — the same order the reading path already produced — with dropped words removed rather than reordered around. Progress reporting is unchanged and still narrates work as it finishes.
- **Subtitle generation reports the transcription stage as soon as extraction finishes (Utilities → Generate).** The "Extracting audio" line stayed on screen until the transcriber produced its first segment, a span that also covers the WAV load, the Silero speech mask, model construction and — on CUDA — the whole first decode window, so a stall anywhere in it read as an ffmpeg problem, and the log had no line to say otherwise. The message now flips to "Transcribing: 0%" the moment the audio is loaded, extraction leaves an INFO receipt with its elapsed time, and both engines log an `ASR model load` line before constructing a model, so a run that stalls — a second folder batch in one session, reported on Windows and not reproducible on Linux — can be placed in the right stage from `anki_miner.log`.
- **A second subtitle-generation batch no longer stalls after a failed GPU attempt (Utilities → Generate).** On a Windows machine with an NVIDIA GPU but no CUDA pack, the first batch's CUDA attempt raised `Library cublas64_12.dll is not found or cannot be loaded` and the batch ran on the CPU; the next batch in the same session tried CUDA again and hung inside model construction, with Cancel unable to reach it. ctranslate2 loads cuBLAS through a function-local static whose initialiser throws when the DLL is missing, and re-entering that static after it threw never returns in the MSVC build (the Linux build re-throws, which is why it never reproduced here). The model is reused within a batch, so the CUDA path was entered exactly once per batch — first entry threw, second hung. The first CUDA failure of a process now disables CUDA for the rest of the session with one warning naming the reason, so every later batch goes to whisper.cpp or the CPU directly; a restart is the only reset.
- **Word-audio fetching no longer stalls a run, and a slow audio pack is named with its remedy.** Two reported runs, one cause each. The first spent 796 s in "Extract media" on a single card: the word's JPod101 fetch succeeded, so every transport counter read zero and no diagnosis fired — `requests`' `timeout=` is per socket operation and bounds neither name resolution nor the endpoint's 301 hop to a second host with `Connection: close`, whose cost escalated with request volume and survived app restarts. The chain walk now runs under one 20 s wall-clock budget per word covering every source and candidate form; expiry is a miss tallied in a `slow` bucket, and the walk is abandoned rather than cancelled (a thread blocked in `getaddrinfo` cannot be interrupted, and member caches are written atomically, so a late success only warms the cache). The second run had only local audio packs in the chain and still took 39-255 s per word before hanging for ten hours across a sleep/wake: a pack index lookup is local SQLite, but every fresh hit copies one file out of the pack's source folder, and that folder sat on a medium where reading data is slow or blocks (the fingerprint — cached hits at 0.00 s, a 138k-entry pack importing in 9 s because `is_file()` is metadata, and three other packs taking 27-80 min to enumerate — is a cloud-placeholder or network folder). The budget bounds that too, but a "slow" count alone could not say which of four packs was on the slow medium, and the generic advice (reorder or disable the source) is the wrong remedy for a pack. `ChainedExpressionAudioFetcher` now records the member that was running when a budget expired: the WARNING line names it, and for a local pack also its source folder, so the next diagnostics bundle carries the one path it was missing; `slowest_pack_id()` hands the pack to the stage, whose diagnosis then names the pack and tells the user to move its folder to a local drive and re-import it (Settings → Audio → Re-import…) instead of pointing at the reorder/disable advice.
- **Importing an audio pack shows that it is working, and can be cancelled (Settings → Audio → Add Audio Pack).** Parsing a large pack reported one static string for up to 45 minutes, and the pre-import folder scan — 68 minutes on a real pack — showed nothing at all behind disabled buttons, so users killed the app mid-import. The parse now reports its running entry count every 500 rows, and the scan gets its own busy dialog naming the folder it is walking, with a Cancel that works.
- **A newly added online audio source goes above the JPod101 fallback (Settings → Audio).** The chain is first-hit-wins and a new source was appended below an enabled jpod101, so it was never consulted for any word jpod101 could answer.
- **The Add Audio Source dialog opens on the JSON kind.** It defaulted to the direct-audio kind while carrying the local-audio-yomichan server name, so the placeholder server-root URL missed on every word.
- **Message-box buttons no longer clip their own labels.** A `min-width: 80px` in the stylesheet resolves to `setMinimumWidth`, which *replaces* the text-derived minimum rather than raising it, and the value had grown to 106 px; QMessageBox then sizes itself from the label alone, so a button wanting more — "Exclude these decks" wants 138 px — was squeezed into the shortfall. The rule is horizontal padding now, so every message box sizes to its longest button.

## [2.14.0] - 2026-08-28

A release about repairing cards you already have and not destroying files you already had. Card Backfill grows a sixth field group, word audio, so mapping the field or installing an audio pack for the first time no longer means re-mining everything to hear it — and it can finally clear the `9999999` frequency placeholder that 2.7.8 through 2.11.0 wrote into unranked cards. Retiming stops writing over the subtitle it read: the output is a `_retimed` sibling, which makes the keep-original guarantee structural rather than a backup copy taken a moment before the overwrite, and lets the `.pre-retime.bak` files go away entirely. Elsewhere, a resource import that crashes mid-promotion no longer locks its family for an hour, and the Download tab gains a 1440p rung between "Best available" and "Up to 1080p".

### Added
- **Up to 1440p quality preset (Utilities → Download).** The quality menu jumped from "Best available" — which takes whatever the site's top rendition is, 4K included — straight to "Up to 1080p", so a 1440p monitor had no rung of its own and the resolution was reachable only by typing a raw yt-dlp format string into Custom format. The new entry sits between the two and uses the same `bestvideo[height<=N]+bestaudio/best[height<=N]` shape as its neighbours, so it merges through ffmpeg exactly as they do and falls back to a muxed stream on sites that publish no separate video track. `config.downloader_format_preset` is a free-form string with a fallback to "Best available" on an unrecognised key, so nothing has to be migrated and a profile written by an older build still loads. The mining fetcher's separate 720p cap is deliberate and unchanged — it feeds screenshots, not viewing.
- **Card Backfill fills word audio (Utilities → Card Backfill).** A sixth field group, gated on `anki_fields["expression_audio"]` like every other optional field, fetching through `config.expression_audio_chain` exactly as mining does — packs, JPod101, custom and Google TTS in the configured order — so installing an audio pack or mapping the field for the first time no longer means re-mining to hear cards you already have. Audio resolves during the read-only scan rather than at apply, which keeps the preview's promise that Apply writes precisely what was previewed: a word no enabled source has never becomes a row, instead of becoming a row that silently does nothing. Apply uploads each chunk's files through the content-addressing media pipeline and writes the name AnkiConnect confirms, so a file mining already stored resolves to the same media entry rather than a duplicate, and a file that fails to upload leaves its field alone rather than pointing the card at missing media (counted and named in the run summary). The candidate ladder is the mining one — katakana-reading variant for loanwords, okurigana-only lemma fallback — moved down from `orchestration/audio_stage.py` into `services/audio_fetch_common.py` so `services/` need not import `orchestration/`, with the synthesis from an existing note's fields in a new `services/backfill_audio.py`. Two supporting changes: `_is_fillable` gains a media branch, because `_is_empty` mirrors Anki's HTML/media-stripped dedup key and therefore strips `[sound:...]`, so a fully-voiced field read as empty and fill-only mode would have re-fetched and rewritten every card that already had audio; and the scan's staleness gate gains the `audio` family, so a schema-stale audio pack stops a word-audio run with the same actionable message the other three families use instead of being dropped from the chain in silence. Unlike pitch, a tokenizer-guessed reading is allowed to fetch and to overwrite — JPod101 refuses a non-kana reading outright and a wrong kana reading misses rather than fetching a homograph, so the exposure is limited to a synthetic source voicing a guess.

### Changed
- **Retiming writes `<name>_retimed.<ext>` and never touches the subtitle it read (Utilities → Retime).** The output path was `video.stem + in_sub.suffix`, which for the ordinary layout — `EP01.mkv` beside `EP01.srt` — *is* the input file, so a run with Overwrite ticked destroyed the user's own subtitle and the `.pre-retime.bak` copy taken just before `os.replace` was the only thing standing between them and a lost original. The name now derives from the input subtitle's own stem plus `_retimed`, so no path the worker builds can collide with the file it read and the keep-original guarantee holds by construction rather than by a copy. Because both files then live in one folder, subtitle discovery has to prefer the retimed one or mining would silently keep parsing the off-timed original: `find_pairs_by_episode_number` sorts a `_retimed` sibling ahead of every other candidate for the same episode (ahead of the `.ass > .ssa > .srt` priority — a retimed `.srt` is a better match for its video than the `.ass` it was made from), and `find_sibling_subtitle` prefers `<video stem>_retimed` over `<video stem>`, which also reaches Condense's subtitle discovery and the Single Episode auto-pick. Retime itself passes the new `prefer_retimed=False` so a rerun retimes the original rather than its own output; the second run then finds the retimed file already there and skips it unless Overwrite is ticked. Skipping is now the only meaning "output exists" can have, so the in-place skip message ("Output equals input; enable Overwrite…") is gone along with the alias detection behind it. Long source names are bounded by the helper Condense already had for the same problem, moved to `utils/file_utils.py` as `bounded_output_name` and shared by both, so a name near `NAME_MAX` is truncated with a hash marker instead of failing the write.

- **Card Backfill's scan progress advances per note, not per 500-note chunk.** Every other proposal is a local lookup, so the old chunk-boundary tick was invisible; word audio is a network round trip per note, which would have left the bar frozen for minutes at a time and made Cancel appear dead until the chunk ended. Cancellation moved to the same granularity.

### Fixed
- **A crashed import no longer blocks the next one for an hour.** The cross-process promotion lock beside each resource family root (`.anki-miner-promotion.lock`) was an O_EXCL sentinel with no liveness check, so a holder that died without releasing it — a crash inside a repair import, which holds the lock across the whole index build, or a Windows AV/indexer handle denying the release unlink — left every later import into that family failing with a raw "[Errno 17] Slot is being promoted by another Anki Miner process" until the one-hour mtime budget expired. The lockfile token now records PID plus process start time, and acquisition reclaims the file the moment the recorded holder is proven gone — a dead process, a recycled PID, or this process's own leaked lockfile — leaving the mtime budget as the fallback for a token no holder can be read out of. Release no longer raises: by the time it runs the promotion has already succeeded, so a denied unlink used to report a completed import as failed and now just leaves a leftover the next acquisition reclaims. Live contention became a `SetupError` with an actionable message ("Another Anki Miner window is importing…") instead of a `FileExistsError`, which the importers rightly translate as "already exists" — which contention is not.
- **Card Backfill clears the old `9999999` frequency placeholder from cards no frequency source ranks.** v2.7.8-v2.11.0 wrote a literal `9999999` into the sort field for an unranked word; the placeholder was removed at mining time in v2.12.0, but Backfill could never repair the cards already carrying one. Backfill only ever writes a value it computed, and an unranked word computes nothing — `_frequency_proposals` omits the sort key and `_compute_note_changes` drops falsy proposals — so the placeholder survived every scan in both fill-only and overwrite mode. `_is_fillable` already classified a stored `9999999` as empty, but that only decides whether a write is *permitted*; it never manufactures one, which left ranked words getting a real rank and unranked ones stuck at `9999999` forever. The scan now emits an explicit clearing change for that case, tightly scoped: only the exact legacy sentinel, only the sort field, only when the current chain ranks the word nowhere. A genuine rank on a now-unranked word is left alone, as is the display field — Backfill does not wipe values the user has just because the current chain no longer produces them — and the scan's existing `is_available()` gate means an unloaded frequency chain cannot reach the clear at all. The preview marks such a row `(cleared)` rather than showing a blank New cell, which would read as a rendering bug rather than as the write it is.
- **A Card Backfill checkbox keeps its own tooltip after being greyed out.** `_refresh_checkbox_gates` replaced a disabled group's tooltip with "Map this field in Settings → Anki" and had no branch to put the original back, so the first time a group went unmapped its explanation was destroyed for the rest of the session — the reading group's "does not generate new readings" note was the existing casualty, and the new word-audio group's scan-cost warning would have been the second. The group tooltips are held separately and restored when the gate reopens.

### Removed
- **`.pre-retime.bak` siblings are no longer written (Utilities → Retime).** The backup existed because a commit could overwrite the input subtitle; now that the output is a `_retimed` sibling, the only file a run can replace is a previous retime of the same pair, which re-running reproduces. Nothing swept the old copies up either — one accumulated per output name and stayed on disk forever — so the file is gone rather than merely deleted afterwards, and `_commit` is a bare `os.replace`. Existing `.pre-retime.bak` files are left alone; they are ordinary subtitles under a `.bak` extension and safe to delete.

## [2.13.0] - 2026-08-26

A release about the two ends of a mining session. At the front: a standalone downloader that saves anything yt-dlp can reach without mining it, YouTube videos whose Japanese exists only as an auto-dub, and a curator that can grow a word's sentence across subtitle cues instead of leaving it cut in half. At the back: a crash-hardening and performance sweep over the whole app, which is why closing a tab after a run no longer takes the window with it, why a 20-hour audiobook is refused rather than killing the process, and why a batch queue stopped rebuilding its entire tokenizer once per item. The bundled yt-dlp moves to 2026.08.19 — the version it shipped with 403s on every YouTube video data request since 2026-08-17.

### Added
- **Standalone yt-dlp downloader (Utilities → Download).** Paste URLs — one per line, any site yt-dlp supports — pick a quality preset (Best available, up to 1080p, up to 720p, audio-only MP3 or M4A) or a raw yt-dlp format string that overrides the preset, and download into a folder of your choice without mining anything. Optional extras: subtitles saved next to the media (manual preferred with automatic fallback, languages default `ja`), embedded thumbnail, embedded title/metadata. Downloads run sequentially through the same supervised subprocess primitive the YouTube miner uses — process-tree kill on Cancel, `--` end-of-options hardening against option-shaped URLs, cookie settings shared with Settings → YouTube — but through a new `MediaDownloaderService` rather than the mining fetcher, which caps at 720p, fails without Japanese subtitles and deletes its workspace after the run: all three are correct for mining and wrong for a downloader. yt-dlp's own collision defaults are kept on purpose: a file that already finished reports "Already downloaded" and is skipped, and a leftover `.part` file resumes where it stopped. A per-URL failure logs and the queue continues; a missing yt-dlp executable stops the whole queue and points at Settings → YouTube → Update yt-dlp now. The run options persist as `downloader_*` config the way the condenser's do; the destination folder is machine-local session state (D7), defaulting to the system Downloads folder.
- **Merge the previous or next subtitle line into a word's sentence and clip (Word Curator).** A sentence split across subtitle cues could only be captured by dragging the clip slider over the neighbouring line — which widened the audio but never the exported sentence, and took real timing effort to land. "+ Previous line" / "+ Next line" under the video preview now merge the neighbouring cue into the focused word's line, and both the card sentence and the extracted media window follow: sentence text, bold span and furigana are rebuilt over the merged text, audio spans first cue to last, and the screenshot is taken from the merged region's start. Presses accumulate (two lines back, one forward); "Reset lines" restores the original single line. Adding a previous line snaps the preview to the new start so it can be auditioned without scrubbing. A direction disables when no cue exists that way or when the merged clip plus padding would exceed the clip slider's 30-second ceiling — the guardrail against merging across a long dead gap between cues. The clip slider composes on top: expanding reseeds the slider to the merged window (dropping any old fine-tune, exactly as picking a different example sentence does), and a drag made afterwards still wins over the default. Sentence-length and duplicate-sentence filters ran before the curator opened and are deliberately not re-applied to a sentence the user grew on purpose (#120).
- **YouTube auto-dubbed videos now mine (Video → YouTube).** A video whose Japanese exists only as a YouTube auto-dub — a Japanese AI dub audio track plus machine-translated Japanese captions — was rejected at Add with "No Japanese subtitles available for this video", because the caption gate correctly refuses machine-translated captions that do not match the audio. When the same video also carries a Japanese audio track, captions and dub come from the same translation pipeline and do match, so the probe now recognises that case as a third route (`auto_dub`, shown as "Auto JA subs (dub audio)" on the row's hover detail) and the fetch pins the Japanese audio track with a `bestaudio[language^=ja]` selector. The selector deliberately has no fallback: if the dub disappeared between probe and download, the fetch fails and says the dub vanished rather than silently mining translated captions against foreign audio — the exact mismatch the gate exists to prevent. Videos with manual or native captions classify exactly as before, including a manual-subbed video that happens to carry a dub: it keeps the original audio, since the manual subs' wording differs from the dub script.

### Changed
- **Curator example sentences wrap at phrase boundaries (Word Curator → Sentences).** Qt breaks spaceless Japanese text anywhere it likes — mid-word, mid-conjugation (行きま / しょう) — which made long candidates, above all the full book sentences reading mining offers, harder to scan than they should be. Candidate rows are now segmented with BudouX (Google's ~15 KB phrase-boundary model, a new bundled dependency) and the display string carries WORD JOINER characters inside each phrase, so the list wraps between phrases the way typeset Japanese does. The transform is display-only: Ctrl+C lifts the pristine sentence via COPY_ROLE, the tooltip shows it, and the candidate model — what gets mined onto the card — is never touched, so no invisible character can reach the clipboard or a card (the lesson of the U+202A dedup bug). ASCII-only rows pass through untouched, since welding "hello world" into an unbreakable run would be worse than Qt's space-based wrapping, and a parser failure degrades to the old unwrapped display rather than raising in a populate path.

- **The bundled yt-dlp is 2026.08.19.** The 2026.07.04 build shipped in 2.12.0 stopped working on 2026-08-17, when YouTube killed the `android_vr` client's https formats: every stable install of that version worldwide returns "HTTP Error 403: Forbidden" on video data. Subtitles come from a different endpoint and still downloaded, so the failure surfaced at the subtitle-conversion step and read as a subtitle bug (Issue #119). Users who already worked around it with Settings → YouTube → "Use pre-release (nightly) builds" keep their nightly; the checkbox is unaffected.
- **Startup, batch runs and dictionary lookups do far less repeat work.** A measure-first pass over the whole app removed work that was being redone rather than making anything new go faster. Boot: the theme gallery is built once instead of per host, service imports are deferred until something needs them, and startup store recovery is answered from the `meta.json` sidecar rather than opening every index. Batch: the queue builds its processor once for the whole run instead of once per item — a new fugashi tagger, discarded parser memos and a re-probed media extractor per queue item — which needed the subtitle offset to become a per-call argument so one offset-neutral tokenization can serve items retimed differently. Per run: a keep-alive AnkiConnect session, one attestation pass per dictionary provider, and memoized known-word and Anki-vocabulary sets, all invalidated by their own writers. Lookups: the glossary CSS is read off the already-loaded provider chain instead of rescanning `dicts_root` and reopening every `index.sqlite` per episode, and `lookup_many` issues one query per chunk rather than one per word. Reading: one zip handle per volume instead of one per page. Subtitle-encoding detection and the parser's per-parse furigana, reading and attested-reading memos are bounded, so a long file cannot grow them without limit.

### Fixed
- **Deck Filter no longer breaks window close after inspecting a source deck.** The close path called `isRunning()` on the inspect worker whose lifetime `run_off_thread` owns and `deleteLater()`s once it finishes, so closing the app after any source-deck inspection raised past `release_dictionary_resources` and `save_config` into the crash dialog — losing the session's settings with it.
- **Yomitan redirect rows resolve to the entry they point at.** JMdict-family exports (Jitendex, yomidevs JMdict) mark search-only spellings as pointer rows — content `⟶ <target>`, roughly a third of Jitendex's rows — and the arrow stub used to render as the whole definition, blocking every lower provider behind it via first-hit-wins. Lookups now splice the canonical entry's rows in at the redirect's rank.
- **Redirect resolution on an existing dictionary install is fast and duplicate-free.** An index imported before the fix above had no `idx_sequence`, so every redirect batch fell back to a table scan; it is now backfilled once on load, guarded against a failure reopening a locked database. Two follow-on bugs are fixed alongside it: a redirect whose target row already sat in the result set was spliced in a second time, and a foreign dictionary's own negative-sequence rows — real content, no arrow — were folded together with unrelated positive-sequence entries that happened to share a magnitude.
- **Duplicate probes survive a busy Anki instead of failing the run.** Anki keeps accepting TCP connections while its main thread is blocked — a sync, a dialog, a database check — so a probe timed out even though every connectivity check read green. The timeout message now names the busy state, and `canAddNotes`/`canAddNotesWithErrorDetail` retry transient transport failures up to three times before giving up, since a read-only probe is always safe to replay.
- **Line expansion in the curator no longer corrupts a card or locks "Reset lines" out.** A cue that no longer matches the word it was resolved against — after retiming, or a stale index — used to expand anyway and scramble the sentence's bold span and furigana; it now bails and keeps the original line when the cue text doesn't match. "Reset lines" stayed disabled whenever the current cue couldn't be resolved, even with an expansion already staged; it now tracks whether anything is staged instead. The prev/next tooltips' "30 seconds" was a hardcoded string next to the `MAX_CLIP_SECONDS` constant it could drift from; they now read the constant.
- **A vanished YouTube auto-dub track fails once instead of retrying three times with the wrong error.** The auto-dub route's "no format" failure was a bare error the queue worker treats as transient and retries, which is pointless once the dub track is simply gone; it is now typed to opt out of retry, the message also covers the paired video stream going missing, and the format selector is anchored so it can no longer match an unrelated language code that merely starts with "ja", such as Javanese.
- **Space keeps playing/pausing the clip anywhere in the curator's player pane.** The shortcut was scoped to the player widget alone, so pressing Space while a clip-strip or prev/next-line button had focus activated that button instead of toggling playback; it is now scoped to the whole pane.
- **The Download tab shows real progress and stops fighting itself mid-run.** yt-dlp's progress fraction reached the UI as a bare word ("Downloading" instead of "Downloading: 42%"); the percentage is now folded into the message. A config refresh landing while a download was running could re-probe yt-dlp and re-enable the Download button mid-run, or overwrite subtitle-language and format-string text not yet committed — the tab now diffs post-normalization and skips the probe when only its own `downloader_*` fields changed. A merge or audio-extract preset with no ffmpeg on PATH used to fail partway through the transfer; ffmpeg is now checked first. An unwritable destination folder now raises a named screen issue instead of a log line easy to miss.
- **Closing a tab or the app after a run no longer crashes it or freezes the window.** The Deck Filter fix above was one instance of a pattern present across the app: a close path calling `isRunning()` on a worker whose wrapper `run_off_thread` has already deleted, or a probe callback writing to widgets that no longer exist. Card Backfill, Utilities, the Anki probe, the setup wizard, the theme gallery, Deck Builder, Single Episode's track and timing probes, and Analytics' refresh all now go through the RuntimeError-safe liveness checks and drop each finished worker instead of accumulating live objects across repeated probes. Separately, the close-time joins that waited up to 30 seconds per queue tab now wait 2 and hand a laggard to the close reaper — Reading fans out to four children, so a stuck worker could hold the window for two minutes with nothing on screen explaining it.
- **Retiming survives an ffsubsync that hangs, and Cancel stops it.** ffsubsync ran in-process, so a stuck alignment took the app's own thread with it and there was nothing to cancel; it now runs as a supervised child with a one-hour ceiling, and cancelling kills its ffmpeg grandchild too. The child re-enters the app through a dedicated entry point because ffsubsync 0.5.1 has no `__main__` and a frozen bundle ships no interpreter to run it with, and its verdict travels as a JSON line rather than an exit code — a low-quality reject writes the original subtitles and exits 0, so the exit code could never have carried it. An hour of its progress output is no longer accumulated in memory.
- **A second running copy of the app can no longer corrupt a config file or a half-finished resource import.** The single-instance guard is advisory — "Continue anyway" is a real button — so two instances can genuinely race. Config and recent-files writes now stage through unique temporary siblings rather than one fixed `.tmp` path that could be byte-spliced by an interleaved write, and promoting a freshly imported dictionary, frequency list, pitch source or audio pack into its slot is guarded by a lockfile beside the family root, not merely an in-process lock. The lockfile carries the holder's identity so a release cannot delete a lock that was taken over from it, a lock older than an hour is treated as crash residue, and a failure to release no longer wedges every later promotion behind a lock nobody can clear. Bulk index writes take an explicit busy timeout instead of sqlite's default, and the `meta.json` sidecar is published atomically.
- **Audio longer than six hours is refused up front instead of taking the app down (Utilities → Generate).** A 20-hour audiobook was decoded whole into memory and the process was killed by the OS with no message. The length is now checked from the WAV header before a single frame is read, and what is read is streamed in chunks into a preallocated buffer rather than held twice over.
- **A runaway download or API response can no longer exhaust memory or disk.** The yt-dlp updater's download loop had a size floor but no ceiling, and its GitHub API reads, the update checker's, and every AnkiConnect response body were buffered with no limit at all. All four now stop at a ceiling and say so. A multi-hour transfer that prints a line per fragment no longer accumulates its entire output in memory either.
- **Condense, Retime and Generate keep working after a folder that has gone missing.** All three disable their run button before dispatching a folder scan and re-enable it from the scan's completion callback — which three early-return paths never called, so picking no folder or pointing at a folder that had been deleted left the tab's run button dead for the rest of the session. Every bail path now completes the callback. A failed rescan also clears the pairing preview instead of leaving the previous scan's pairs on screen.
- **An unreadable browser cookie database points at the app's own remedy (Settings → YouTube).** A user whose Chrome cookie database could not be read saw yt-dlp's raw error text and a link to yt-dlp's issue tracker in a queue-row tooltip, while this app's fix for that exact failure sat unused: the classifier matched only "database is locked", which no yt-dlp release emits — both browsers copy the database before opening it, so sqlite never reports a lock. It now matches the three failures yt-dlp really reports, each with the remedy that fits it, since "close the browser" is wrong for two of them. The metadata and playlist probes did not classify their errors at all; both now use the same classifier, and the downloader and the miner say the same thing about the same cookie source.
- **yt-dlp validation waits for a busy binary instead of reporting it broken.** Startup validation overlaps the scheduled auto-update, whose brief checksum-and-version hold made a perfectly healthy install report an empty version with a warning. Validation now waits ten seconds for the lock; a real multi-hour transfer still reports busy rather than parking the validation worker behind it. The lock itself is released before spawning any non-managed yt-dlp, so a long download no longer starves callers that only need to resolve a path.
- **Expression audio can no longer abort a run.** The JPod101 and audio-pack fetchers promise never to raise — the phase-3 loop calls them with no `try` by design — but caught only network and sqlite errors, so a malformed URL or a kana-helper failure escaped and took the run with it.
- **A corrupt page archive no longer strands the rest of a volume's file handles (Reading → Manga).** One archive raising on close skipped closing every archive after it.
- **Background tools no longer stop dead when the app is launched from a terminal.** Every subprocess the app spawns now detaches stdin; one that inherits the terminal's can be suspended by the OS the moment it reads from it. The condenser's ffmpeg is also wrapped so its pipes close on every exit path, and the Vulkan device probe no longer flashes a console window on Windows or races a second probe.

## [2.12.0] - 2026-08-20

A correctness release with one large rewrite behind it. Retiming stopped being a single `alass` call whose output was written out unconditionally and became a clean → align → validate → commit pipeline over four alignment candidates, with the guarantee that a subtitle it cannot improve is left exactly as it was. Alongside it: three parsing and lookup fixes that change which word a card fronts and what its back says, the audio pack staleness gate that brings the fourth resource family up to the other three, and a curator that can take a Known Words mark back.

**One thing to know before updating.** The nominalization fix changes the front some words card under: お願いします now mines お願い rather than 願う, お帰りなさい mines お帰り rather than 帰る, and ご存じですか mines ご存じ rather than 存じる. Those words card once more under their new front, and the old cards are not migrated.

### Added
- **Pick one card image for pasted text (Reading → Text).** Text mining has no video frame and no page scan behind it, so its cards were the only ones that came out with no picture at all. A card image can now be chosen once and is shared by every card mined from that block of text — one file read, one Anki media upload, one filename, however many words the text yields. A pre-run gate checks the file before the run starts rather than failing per word deep into it: a path that has since been moved or deleted, a format Anki will not display, and — folded in from this cycle's review — an image picked while the Picture field is left unmapped in Settings → Anki, which used to run to completion and quietly write cards without the image the user had just chosen. All three now stop the run up front and name what to change.
- **Re-run a series the queue has already finished (Video → Batch).** A completed series row could only be mined again by clearing the queue and adding the folder back, which lost the rest of the queue with it. Selecting a completed series and running it now resets that row's own run history and mines it again; a queue in which every row is complete points its action bar at "Run selected" instead of a "Run" that had nothing left to do. `reset_for_new_inputs` is renamed `reset_run_history` to say what it actually clears, and the worker's PENDING-only gate is unchanged — a re-run moves the row back to PENDING rather than teaching the worker to pick up completed rows.
- **Take a Known Words mark back in the Word Curator.** "Add to Known Words" flips to "Remove from Known Words" once every target row is already staged, so a row marked by mistake is unmarked in place. Until now the mark was one-way inside the review — `_mark_row_known` strips the row's checkable flag, and nothing cleared the stage but a successful Confirm — leaving Cancel as the only escape, which discards the whole review and, because `MiningTabBase._resolve_curation` reads a rejected curator as a run-level stop, cancels the run with it. A mixed selection still stages the rest rather than unstaging, matching what the label says. Nothing about the deferred write changes: both directions write nothing and Confirm remains the only writer (D34-B). The unstage restores the row's pre-stage check state instead of defaulting to included, and the stage is re-derived from the table rather than reference-counted, so two rows printing the same mined form cannot have one unstage clear both. Removing a word already committed to the list is unchanged: Settings → Filtering → Manage Known Words.
- **Audio packs have a visible reimport path.** The panel gained a "Reimport All" button and, on a stale row, a per-row "Re-import" button — matching the other three resource lists. A stale pack has shown "⚠ re-import required (app upgrade)" since the 2.10.0 index bump, but the only way to act on it was a context-menu item nobody could find. Unlike the other three families a pack keeps no `source.<ext>` copy inside its slot — a pack is gigabytes of audio and is never copied — so the batch rebuilds from the absolute source recorded at import time (`meta["pack_dir"]`, or `meta["source_db"]` for an Android database). A pack whose recorded source is gone is reported in the summary rather than prompted for, since a batch that stopped on a folder picker per pack would strand the user mid-upgrade. The startup prompt now covers all four families and still runs their batches in sequence. An `android_db` pack re-imported in place also purges the cached handle the old index left behind, so the repaired pack is consulted on the next run rather than the run after a restart.
- **The error banner can be put away, and a fresh attempt clears the last one.** D24 leaves a screen's issue banner up until "the caller, on success" clears it — a success 81 of the 96 reporting sites never have — and the banner carried no close control, so a sentence the user had already read stayed on the screen with no way to acknowledge it. It now has a dismiss button (translated accessible name; still no auto-dismiss timer, and that refusal is now pinned by a test), and starting a run or a scan supersedes whatever the previous attempt complained about. Validation refusals such as "No valid series in the queue to process." were the worst case: they have no success path at all, so they outlived the run the user then went on to complete. The clear is placed at each run entry point after the reentrancy guard and before the first validation branch — not on the action bar's `clicked`, where Qt connection order would fire it last, and not at `_publish_task_start`, which Batch's "was skipped" warnings are raised before reaching. Opening a track picker or the timing probe is not an attempt and no longer clears anything: five probe entry points were wiping a real, unfixed run failure the moment the user looked at a picker.
- **A pre-release channel for the bundled yt-dlp (Settings → YouTube).** YouTube extractor breakages are usually fixed in yt-dlp's nightly builds days before they reach a stable release, and the in-app updater only ever saw the stable repository. "Use pre-release (nightly) builds" points the updater at the nightly repository instead; it is off by default, and nothing about how the download is trusted changes — the nightly repository is the same publisher, carries the same per-OS asset names, and publishes the same `SHA2-256SUMS` manifest the installer already verified against.

### Changed
- **Retiming is a self-tuning pipeline that never destroys a usable subtitle (Utilities → Retime).** It was one `alass` call whose result was written out whether or not it was any good; it is now clean → align → validate → commit, with four alignment candidates tried in order until one survives validation: ffsubsync split, alass split, alass single-offset, ffsubsync single-offset. The fourth exists because alass is not installable in-app on macOS, which left that platform with one candidate. **When every candidate fails validation the input and output files are left exactly as they were** and the outcome says why — a bad sync can no longer overwrite a subtitle that merely needed a different engine, which is what the removed single-offset default had been doing to cross-release retimes. A commit that does overwrite an existing output copies it to `<name>.pre-retime.bak` first. Alignment runs against a dialogue-only copy of both files — signs, songs, `♪` markers, HoH annotations, drawings and comments are stripped — and the winning timings are mapped back onto the untouched original by nearest-anchor block shift, so every line and all ASS styling survive the round trip; your own file is never edited in place. The validator rejects the wrong-optimum signatures aligners actually produce (implausible shifts, scrambled cue order, a 00:00 pile-up, cues past the end of the video, bogus span scaling, and an engine's own warnings); `ok` from an engine only ever means the tool ran to completion. An auto-picked embedded subtitle track must now cover at least 60% of the episode, which rejects the untitled signs and recap tracks that passed the title and disposition checks, and the audio fallback says "first audio track (no Japanese tag)" and warns it may be a dub rather than claiming it detected Japanese. Folder mode shows the matched video ↔ subtitle list, and the unmatched videos, as soon as both folders are chosen — mispairing was the silent destroyer of whole-season retimes — and the pipeline's own working files are kept out of that pairing namespace so a retimed output cannot be picked up as an input. A missing alass shortens the chain instead of stopping the queue, and the tab shows a notice instead of disabling retiming outright. Every decision, per-engine verdict and offset is narrated to the run log in the user's own language, and the durable Activity log — not just the transient status line — carries the winning engine's name and the `.pre-retime.bak` sibling when one was written. ffsubsync is a new dependency and is bundled in the app.
- **The Yomitan dictionary import is faster and its progress bar means something.** `idx_term` and `idx_reading` were created alongside the tables, so an import maintained two B-trees across every one of a million inserts; the index DDL is now split out and built once after the bulk load, sharing a connection with the rollback journal and synchronous writes off. Both only ever touch a staging database that is renamed into place after the import succeeds, so a crash leaves discarded bytes rather than a promoted half-built index. The insert phase also stopped being indeterminate: the row total is unknown until the last term bank is parsed, so it now reports banks done out of bank total — the one denominator known before the first bank opens — and a separate optional per-bank callback reports the same for a consumer that cannot render a count without a fraction. Progress is clamped to its total so a bank whose row count exceeds the estimate cannot push the bar backwards or past the end, and the entries readout shows the real entry count once the load returns instead of freezing on the last bank number.
- **The curator offers every example sentence a word appears on, not the first twelve.** `attach_sentence_candidates` and `merge_pools` truncated the pool at twelve, so a word usable on 34 lines silently offered 12; the picker scrolls, so it now offers all 34. Because an unbounded list needs a count — five visible rows read as five options — the Sentences pane title carries the number of options, and the Occurrences header explains in a tooltip why the picker usually lists fewer than the occurrence count: repeats on one line count once, and lines that would change the card's Word are skipped. The picker also reserves its scrollbar gutter permanently, since word-wrapped rows re-flowed left and right every time the scrollbar appeared or vanished with the focused word's candidate count.
- **A schema-stale audio pack stops a run instead of being dropped from the chain in silence.** `build_fetcher_chain` drops a stale pack, so the run reported success while cards fell through to the online sources or got no audio at all, with nothing but a log line naming the cause. Every mining path now aborts once with the same actionable message the other three families use, and System Health carries an "Audio packs" row. This reverses an earlier call to leave audio out of the gate on the grounds that a stale pack costs only expression audio — cost is not the test the other three are held to, since frequency and pitch are optional too and they gate; what the gate exists to prevent is a silent wrong result. The registry handle is threaded from `service_factory` into the `EpisodeProcessor` so the per-episode gate costs no extra disk I/O, and it is built only when the `expression_audio` field is mapped and an enabled pack entry exists — the same two conditions under which a pack is ever consulted, so a user who configured no pack stays ungated and reads as "not configured" rather than a green tick. Card Backfill does not gate on it: `FIELD_GROUPS` has no expression-audio group, so backfill never writes pack audio. The startup prompt's wording follows the gate: a stale set that is audio packs alone now says mining is blocked too, instead of naming the family and leaving the consequence to be inferred from the other three.

### Fixed
- **A word no frequency source ranks leaves the sort field empty instead of claiming rank 9999999.** v2.7.8 started writing a 9999999 placeholder into the field mapped to FrequencySort so unranked words would sort after rank 1 rather than before it; it reads as a real, absurd rank on the card, and because the write was gated only on the mapping and never on a frequency source being loaded, a user who applied a note-type preset (Lapis, Kiku and Senren all auto-map the field) without installing a frequency list got it on every card mined. Nothing is written now — no rank, no value. Card Backfill drops the matching placeholder proposal and its summary counter with it. Cards already carrying a 9999999 are repaired by a normal Card Backfill run: the value is treated as empty for that one field, so fill-only mode replaces it with the real rank once a source ranks the word, where before only Overwrite mode or re-mining could shift it. A word that is still unranked keeps its old placeholder — backfill fills, it never blanks.
- **A word written as a verb stem but used as a noun is mined as the noun.** `これ、差し入れ` / `みんなで食べてよ` mined 差し入れる, and `ご存じですか` mined 存じる. Two separate causes. A subtitle cue's line break arrives as a plain space, which MeCab does not treat as a sentence boundary, so it read 差し入れ as the stem of 差し入れる; the same line punctuated with `。` was always correct. A 連用形 stem is now mined as the noun when the dictionary attests it and the next word cannot follow a verb stem, so 帰りましょう, 疲れた, 笑いながら and 動き出した keep their verbs. Separately, the compound matcher only ever looked up ご + the dictionary form of 存じ — ご存ずる, which no dictionary lists — and never ご存じ, which both bundled dictionaries list as a noun; an honorific prefix followed by a verb stem now also tries the written form. This changes お願いします to mine お願い rather than 願う, and お帰りなさい to mine お帰り rather than 帰る, so those words card once more under their new front. The reading the nominalized word carries is unidic's context-disambiguated one and is now locked against dictionary attestation: attestation exists to fix the reading of a *merged compound*, and applying it to a 1:1 nominalization let the dictionary's entry for an unrelated homograph of the same surface overwrite a reading that was already correct.
- **A kana front gets the definition of the word actually used.** そうゆう, ゆった and どうゆう are kana spellings of 言う, and they mine as ゆう — a spelling no dictionary lists as a headword, so the lookup fell through to a scan over folded readings, which ranks 有, 夕 and 結う above it and then drops 言う entirely at the five-sense cap. The card front said ゆう and the back defined "evening". Where a front has no exact dictionary row but rows exist for the token's own lemma, those rows are now what the card gets; kanji fronts are unreachable by this rule by design, and the existing precedence between the other homograph rules is unchanged. The curator's definition pane follows the same scope — it was calling the offline lookup with no lemma at all, so it showed every same-reading homograph next to a card that would be written with one — and its lookup cache is keyed by `(term, lemma)` rather than by term alone, since upstream dedup is by lemma and two rows can share a mined form under different lemmas (ゆう from 言う and ゆう from 結う), which had the second row silently reusing the first row's answer.
- **A skipped file is reported as skipped, not counted as a success.** Generate, Retime and Condense counted a skip toward the processed total, so a run that did nothing still finished on "Complete - N files processed". Skips are now counted separately and carry their reason into the log and the task detail, the completion line reads "N processed, M skipped", and a run in which everything was skipped names the remedy instead of claiming success — including on the global surfaces, where an all-skipped run had still been publishing a successful outcome. Same-folder Retime was the silent case: an output path equal to the input subtitle skips every pair, and the run reported a clean sweep.
- **Condensing works on ffmpeg 9, and refuses a build whose `aselect` is inert.** ffmpeg 9.0 removed `-filter_script` in favour of the generic `-/opt <path>` spelling, so condensing against a system ffmpeg 9 aborted with "exit 8: Error splitting the argument list: Option not found"; `-/filter:a` needs ffmpeg 7.0 or newer, so no single spelling spans the supported range and the app probes once, caches, and picks. The same probe catches builds whose `aselect` passes every frame whatever the expression — Ubuntu's `ffmpeg 8.0.1-3ubuntu2` is one — which had been writing the entire source track out under a condensed file's name; that is now fatal for the batch, like a missing encoder. The bundled ffmpeg is 8.1.x and accepted either spelling, so this only ever affected installs running a system ffmpeg.
- **Folder pairing no longer depends on the order the filesystem happens to list videos in.** `iterdir()` order is filesystem-dependent, and with collapsed episode numbers it silently decided which subtitle each video was given; the subtitle side was already sorted, and the video side now sorts by NFC name. This applies to all six pairing call sites — Batch, the batch queue worker, the queue panel, Deck Builder, Retime and Condense. Retiming's own working files are also excluded from that namespace, so a file the pipeline wrote cannot be paired as an input on the next pass.
- **Accepting the startup "re-import these" prompt works.** Index prewarming started alongside the stale-resource scan and holds the very indexes a repair has to rebuild, and `release_dictionary_resources` refuses outright while prewarm is running — so accepting the prompt failed on every family, for every family. Prewarm now starts from the scan's continuation instead: once nothing is pending, or once the repair chain has drained. The prompt's confirm button also names the action ("Reimport All") rather than answering Yes, so the dialog no longer has to spell out in its last sentence what Yes was going to do.
- **A resource scan overtaken by a newer one no longer strands the settings panel.** `_run_latest_scan` dropped both callbacks when a superseded scan's result arrived late, so the startup family-repair chain stalled on the completion that never came and reimport-all's mutation token leaked, refusing every panel mutation for the rest of the session. The supersession is now reported through the caller's own error path exactly once, so each call site's existing cleanup still runs — and because that path hardcodes a "could not be scanned" sentence, the superseded marker is recognised and logged rather than raised as a banner announcing a failure that did not happen. Separately, audio pack reimport-all's nothing-to-do message now distinguishes a pack the startup scan found but the user removed before the repair ran from a chain with no packs in it at all.

### Removed
- **The three retime alignment settings.** "Split penalty", "Correct frame-rate differences" and "Shift by a single offset only" are gone from Settings → Transcription & Alignment and from the config; the pipeline tunes itself by trying candidates and validating them. This supersedes the 2.10.0 entry that moved them there and made single-offset the default — that default silently destroyed cross-release retimes, which is the failure the candidate chain and the keep-original guarantee exist to prevent. The Retime tab's link to those settings is replaced by a note that alignment is automatic.

## [2.10.0] - 2026-08-14

A feature release standing on a large correctness audit. Deck Filter turns a premade deck into one worth studying, batch mining reviews a whole season's words in one pass instead of once per episode, condensed audio can carry music-library tags, and the note type you already use has a preset. Behind them sits an audit of thirty-four areas — over a hundred and thirty findings across card writing, run reporting, the resource chains, cancellation, and the reading and subtitle sources.

**One thing to know before updating.** **Re-import your dictionaries, frequency lists, pitch sources and audio packs** once: all four index schemas moved, and an out-of-date source is flagged in Settings and sits out of the chain until you re-import it.

### Added
- **Deck Filter turns a premade deck into one worth studying (Utilities → Deck Filter).** Point it at a shared deck already in Anki — Core 2k, a Tango deck — and it copies only the notes your filters keep into a new deck; known words, the frequency band, the blacklist, script type and the name wordsets all apply. "Scan deck (read-only)" reports what would be kept and counts every drop by reason, with a preview table, before anything is written; the copy step then creates the new deck and tags each note `anki-miner::deckfilter`. The source deck is never modified and notes keep their note type and field values, so existing images and audio still resolve without re-uploading. The known-words check excludes the source deck itself, and the corpus-only filters (i+1, sentence length, sentence dedup, episode count) are skipped by design. Editing settings between the scan and the copy invalidates the plan and asks for a re-scan.
- **Batch mining reviews words once per series, not once per episode.** "Review words before mining" on Video → Batch now opens the curator a single time covering every episode: a capture pass runs first, the candidates are merged and deduplicated across the season, and cards are written afterwards from what you kept. A word appearing in several episodes is one row carrying its sentence variants (up to twelve), each labelled with the episode it came from, and focusing a variant from another episode swaps the video preview to that episode. A twelve-episode season is one review instead of twelve, and a word recurring across it is reviewed once. Still off by default; the single-video tab is unchanged.
- **Condensed audio can carry music-library tags** (#113). "Tag output files (title, album, artist…)" in Utilities → Condense opens an editor once, after validation and before any encoding, pre-filled per file from the filename: title, album from the season, artist from the series, and the track number, with a genre and cover artwork you can apply to every row at once. Release-tag junk (`x264`, `1080p`, CRC32) is stripped so it cannot be mistaken for an episode number. Tags are written as ID3v2.3 for `mp3` and VorbisComment for `opus` and `flac`. Off by default; because tagging runs after the audio is finished and moved into place, a tagging failure is reported as a warning and never fails the run.
- **The Linux `.deb` ships everything the AppImage ships.** Bundled ffmpeg, libmpv, and both local transcription backends (faster-whisper and the Vulkan whisper.cpp engine) are included again; models download in-app as on every other platform. The stripped "lean" deb is gone - stripping the package directories never removed the pure-Python halves baked into the executable, so the app believed the engine was present and offered a Download button that could not work (the v2.9.x "Download model does nothing" report). The deb no longer depends on system ffmpeg and recommends `libvulkan1` for GPU transcription.
- **Frequency filtering takes a range, not just a ceiling.** Settings -> Filtering now carries one "Frequency Rank Range" row with both ends: a minimum drops the words that are everywhere and already known from exposure, the maximum keeps working as before. Either end can be left open, and the row keeps the band ordered as it is edited.
- **A preset for the note type you already use.** Settings -> Anki gained a Preset row: pick Lapis, Kiku or Senren and every field mapping is filled from that note type's own published field names, along with the two settings nobody can guess - pitch categories switch to the romaji spelling all three read, and Senren's card-type markers take their own names. The first-run wizard applies the right preset by itself when it recognizes the note type's fields.
- **A switch for words no frequency list ranks.** "Include Words Missing from the Frequency List" decides what happens to a word carrying no rank. It is off by default, which is what a rank ceiling has always done; turning it on is what a minimum-only range usually wants, since an unranked word is no more likely to be a common one.
- **Trim a word's audio clip in the curator.** A range slider under the video is seeded with the exact window ffmpeg would cut, and either end can be dragged — or nudged from the keyboard, arrows for 0.1s and PageUp/PageDown for 0.5s — so a clip cut off mid-word or running into the next speaker can be fixed before the card is made. The ▶ button plays just that window, double-click restores the default, and only the focused word is affected. The edited bounds are used as-is with no padding added on top, and the same window feeds the animated screenshot when it is set to match the audio. Clip length is clamped to 0.2-30s and the handles travel at most 3s past the seeded window; switching a word to a different candidate sentence drops its clip edit, since the window was measured against the old line.
- **The Usage Guide covers 33 features it never listed.** Mining subtitle files without video, the word curator, the name wordsets, sentence TTS for reading, the note-type presets, GPU transcription packs, and the menu-only tools — System Health, the setup wizard, session recovery, undoing a run, the keyboard shortcuts — all show up in search now. Menu-only entries say where they live instead of offering an Open button.

### Changed
- **Re-import your dictionaries, frequency lists, pitch sources and audio packs.** All four index schemas move forward (dictionary 5 → 6, frequency 2 → 3, pitch 2 → 3, audio packs 1 → 2) because keys are now stored NFC-normalized, and a fix to how a key is stored cannot apply to an index built before it. The loaders now accept only the current version rather than a range, so an older index is flagged in Settings and sits out of the chain until you re-import it. Same shape as the 2.9.0 note.
- **Retiming aligns against embedded subtitles when the video has them.** Alignment used to always extract the audio and align against detected speech. It now prefers an embedded text subtitle track and matches it cue to cue, falling back to audio only when there is no usable track — on a 60-cue fixture desynced by 11.3 seconds that is a 20ms median residual in 0.1s, against a full audio extraction before. Signs/songs, forced, karaoke and commentary tracks are rejected three ways (title, ffprobe disposition, and a 30-cue floor after cleaning), and the extraction is cleaned in a temp copy — your own subtitle file is never touched. Every choice and every degradation is narrated in the run log, and nothing refuses to run: each failure falls through to the next candidate and finally to audio. The "Audio track:" row is now "Align against:", defaulting to "Auto - embedded subtitles, or audio"; its "Change…" dialog lists subtitle tracks first, then audio, with image-based tracks shown but unselectable.
- **Retiming's three alignment knobs moved to Settings → Transcription & Alignment**, where they persist instead of resetting to defaults on every launch: "Split penalty", "Correct frame-rate differences", and "Shift by a single offset only". **Single-offset is now on by default** — Japanese media rarely has ad-break cuts, and segmented alignment on a subtitle that is merely offset stretches the timing and makes it worse. Uncheck it to allow segmented alignment. The Retime tab links straight to the settings page. Split penalty is clamped to 0-1000 on load so a hand-edited config cannot break every run.
- **"Treat Kana Spellings of Known Words as Known" moved** from the Known Words Database section to Script Type, in the same Settings → Filtering panel. Same setting, same behaviour.
- **All 11 interface translations are complete.** Every catalog is at full coverage, so the strings added this release — Deck Filter, the Usage Guide, the note-type presets, the frequency range — no longer fall back to English.
- **"Find a Feature" is now the Usage Guide, with its own button on the menu bar.** It sits right of Tools (still F1) instead of hiding inside the Tools dropdown. Stale entries were corrected along the way: the subtitle-regex entry now opens the Filtering page it actually lives on, the frequency entry describes the new rank range, and entries no longer promise controls that do not exist (a YouTube quality cap, a part-of-speech picker).

### Fixed
- **Diagnostics bundles redact URL credentials.** A custom audio URL carrying embedded userinfo was written verbatim into the Export Diagnostics zip, in the settings snapshot and in the log lines recording a failed fetch. Such URLs are now reduced to `<redacted-url>` at log-write time and in the snapshot, including lines already present in the log, and query strings are reduced to `REDACTED`; a credential-free URL still records its scheme, host, port and path.
- **Anki gets the notes a run confirmed, and nothing else.** Stop takes effect during a card write instead of being ignored until the whole batch has landed; a word sitting in a deck you excluded is no longer rejected as a duplicate of itself; Deck Builder keeps the edits you make after Preview instead of committing the pre-Preview list; audio and images are no longer uploaded for notes that were never created; and dictionary media that Anki renames on import no longer leaves the card pointing at the old filename. Undo can no longer delete a word a *later* run mined, repeated Undo stops driving the session card count below zero, and Restyle stops reporting success for updates Anki never confirmed.
- **Cards carry the right audio and the right clip window.** A Japanese track tagged `ja-JP` is picked instead of falling through to the first audio stream — the "my cards have English audio" report — and a commentary track no longer outranks the default Japanese one. Condensing uses the full dialogue subtitle stream rather than a forced-subtitles stream. Clips starting near zero no longer stretch past their padded end, on the normal path and the animated match-audio fallback alike. Picture-only audiobooks with no cover no longer drop every word. A re-imported audio pack stops serving the broken pre-repair cached audio, a non-audio HTTP response can no longer become card audio on the strength of its content-type header, two packs fetching at once no longer collide on one staging file, and failure totals no longer leak from one queue item into the next.
- **Card Backfill fills each note from the word it actually matched.** It no longer falls through to a different-kanji lemma when the frequency lookup misses, no longer writes an unrelated homograph's glossary after a lookup miss, and no longer gives two notes with distinct readings both the first one's dictionary entry. It respects the out-of-date-dictionary gate instead of running against a stale index, reports note updates Anki rejected instead of hiding them, and stops definition lookups when you cancel mid-scan. An overwrite can no longer replace the card's Expression through a duplicate field mapping, setup no longer accepts a mapping mining will refuse, a validation result missing an outcome no longer counts as "all passed", and a missing pitch source is named on the approval screen before you press Apply.
- **Dictionary, frequency and pitch sources behave like the ordered chain you configured.** A frequency CSV labelled by raw counts no longer inverts commonness, Yomitan frequency values with decimals are kept rather than dropped, and pitch patterns containing commas no longer break delimiter detection. Two sources with similar names no longer overwrite each other's slot, and words stored in decomposed Unicode now match normalized mined words. An entry that would render to nothing is never stored, so an empty top-chain row stops suppressing every dictionary below it, and JMdict sense restrictions are kept. One missing source no longer drops every source beneath it — the order is preserved and the missing one named. A source you deleted stays deleted across a restart, a resource cannot be replaced while something is still reading it, and a second download of the same resource is refused with the running one revealed instead of started twice. Audio, frequency and pitch sources gained Restore from Disk.
- **A finished run reports the run it actually had.** A batch with failed items no longer paints a green "Complete"; failures show as failures and partial results keep their counts and outcome. A retry reports the cards that retry made, not your lifetime total. A partial write failure no longer wipes the run's word counts, and a phase that produced nothing while you were pressing Stop no longer reports success. A finished run with zero cards stops sitting at "Ready to process", the elapsed clock starts with the run rather than after the first item and keeps ticking between them, skipped files no longer leave overall progress an item behind, a queue warning no longer erases the non-fatal media failures underneath it, a failed update check is reported as failed instead of healthy, and difficulty statistics stop counting the same unique-word total twice.
- **Stop stops, Cancel cancels, and closing a screen ends its work.** "Finish current" no longer claims and mines one extra item, in any queue type. An item that failed and was restored now goes through the probe Retry requires. Cancel interrupts an active streamed audio download, a reading-source load and a definition lookup, instead of being noticed only once they finish. Closing the Reading or Video screen no longer leaves a just-spawned worker running past teardown, closing the known-words import dialog stops the import, export callbacks no longer fire into a closed dialog, and cancelling during the checksum fetch of a tool download no longer installs it anyway.
- **YouTube queues and the bundled tools resolve what you gave them.** Watch Later and other short playlist IDs expand as playlists instead of being treated as single videos, raising the item cap mid-resolve expands the queue to the new cap, a download failure shows the real error rather than a routine SABR warning masking it, and a malformed bracketed URL is rejected at Add. A failed bookkeeping write no longer destroys the working bundled yt-dlp you already had, an in-flight update can no longer build arguments for the old binary and run the new one, and the app's own probes stop reading your personal yt-dlp config. A yt-dlp or alass path override that is not executable is reported as unusable, and deleting an override stops blocking fallback to the bundled tool. Transcribing a queue loads the speech model once instead of per file, one transient failure of the C++ backend no longer blacklists it for every remaining file, and a half-downloaded Vulkan pack no longer enables the known-bad decoding path.
- **Reading sources and the word curator survive the books you feed them.** A manga page with out-of-range text-box coordinates no longer kills the app, two pages whose filenames normalize to the same string no longer attach the wrong image to a card, and a malformed volume inside a folder is reported instead of silently vanishing from the mine. Text detection runs off the interface thread so the window stops freezing during it, curator search matches text in the hidden part of a long sentence, manga pages are cached instead of re-rendered on every focus change, a clip preview reaching the end of the audio reports that it finished, and running out of memory while loading a known-words file is reported as a failure rather than an optional-source warning.
- **Subtitle input, retiming and condensing keep the file you pointed at.** A folder that cannot be read reports the problem instead of aborting Generate and Retime, EUC-JP subtitles decode as Japanese rather than Korean, and Generate accepts the audio formats it advertises when given by folder or drag-and-drop. Condensing a folder no longer drops one of two media files sharing a filename stem. A failed save no longer truncates the existing run log, and names near the length limit or carrying suffixes write atomically instead of failing. A run records the files selected when it started, so changing the selectors mid-run no longer rewrites or clears the result; Test Timing no longer applies the previous source's parse; and switching audiobooks no longer keeps the previous auto-filled subtitle attached.
- **Settings, profiles, connection and first-run setup do what the control says.** A probe result is applied only to the endpoint it tested, a leading or trailing space in the AnkiConnect URL is trimmed, deck names refresh on every Add Deck, a stale reply is discarded after you change the endpoint, and wizard completion and Auto-Map reset when the endpoint or note type changes. Recheck rechecks the note type instead of opening documentation, the frequency warning links to the frequency panel rather than Dictionaries, and a final setup failure now offers a recheck action. The Usage Guide searches the translated titles it is showing you. A failed "New from Current" no longer leaves an unwanted profile behind, CJK profile names and Windows reserved device names no longer block profile or source creation, and an unreadable profile directory is reported as unreadable rather than empty. A custom theme with a bad colour value or excessive nesting is rejected up front instead of aborting startup, an out-of-range parallel-worker setting is rejected when the config loads, and file names that look like markup display literally instead of being rendered.
- **Subtitles in cp932 retime instead of failing.** The detected encoding is now declared to alass on both the subtitle and the reference path under its WHATWG name (`shift_jis`); cp932 is the routine encoding for Japanese subtitle downloads, and alass used to fail outright on it. The reference is always written as UTF-8.
- **The app no longer crashes while quitting.** A SIGSEGV during interpreter shutdown, after the window had already closed, produced a garbage exit code and appeared and disappeared with unrelated changes. The window is now destroyed and deferred deletes drained before exit.
- **Batch progress reflects the episodes, not just the series boundaries.** In Multi-Series Queue runs the overall bar moved only when a whole series finished, so a one-to-three series run read as blank or stuck throughout; it now fills within a series from real per-episode counts. In a short window the queue list could also shrink below one card and clip a row's Edit and Remove buttons; its minimum is now the measured height of the first three visible cards.
- **The word curator fits a 1024px screen.** The search field carried a flat 200px minimum that scaled with nothing — a quarter of the dialog's width floor — so on systems whose default sans-serif resolves wider the dialog could exceed the screen. The floor is derived from the font now, and the filter field grows with the window instead of demanding a fixed width.
- **Distributions carry the licence notices they owe**, and model and recommended-resource downloads are pinned. The local-audio MIT notice was missing from every distribution, the libopus BSD notice from the macOS libmpv build, and the Vulkan loader's Apache licence from the Windows build; two dependencies floated unpinned in the release constraints. Model and resource downloads now name an immutable revision and an expected digest instead of fetching whatever currently sits at the URL.
- **Transcription no longer drops to the slow CPU path when the CUDA GPU is busy.** With device on Auto, a machine with an NVIDIA card always tried the CUDA engine first; if CUDA could not start - the card's memory taken by a game, or the CUDA pack not installed - the run silently fell back to CPU even when the Vulkan engine and its model were sitting there ready. Auto now retries on the Vulkan engine before settling for CPU, and the downgrade is logged as a warning either way.
- **Generate no longer refuses to run for GPU (Vulkan) users.** The pre-run check only looked for the standard transcription model, so a machine with just the Vulkan model installed was told "the model is not installed" even though the run would have used the Vulkan engine. The check now accepts whichever installed model matches the selected device.
- **A failed transcription-model download keeps its error message on screen.** The label used to flip back to "Not installed" milliseconds after the failure text appeared, because the post-download refresh rewrote it from on-disk state; a failed download changes nothing on disk, so the refresh is skipped and the reason stays readable.

### Removed
- **The "Strip subtitle annotations (SFX captions, speaker tags, inline furigana)" setting** (Settings → Filtering). Annotations are always stripped now — full-line sound effects such as （電話）, leading speaker tags and inline furigana like 瀕死(ひんし) — in mining and in the curator and timing views alike. It defaulted to on; if you had turned it off, stripping is back with no switch, and the Subtitle regex filter below it still composes on top as the escape hatch. The 2.8.3 entry advertising this checkbox is superseded.
- **The "Skip katakana-stylized subtitle cues" setting** (Settings → Filtering). It dropped an entire cue containing katakana but no hiragana, which also sacrificed valid loanword-only lines; such cues are always mined now. It defaulted to off; if you had turned it on for a source that renders one speaker in katakana, a Subtitle regex filter entry replaces it.

## [2.9.3] - 2026-08-08

A crash fix and a filter fix. On Windows the word curator killed the app the moment a line played — the crash capture added in 2.9.2 was treating mpv's own routine internal exceptions as fatal, and the dump it took to record them is what actually ended the process. The kana exclusions also missed the words most people tick them for.

### Fixed
- **The word curator no longer takes the app down on Windows when a line plays.** The video core was loading mpv's builtin Lua scripts — a statistics overlay, a console, a few menus, none of which this player uses — and LuaJIT raises Windows exceptions as ordinary, caught control flow. The native-crash capture added in 2.9.2 treats every one of them as fatal and dumps all threads, and taking that dump while the player thread is running is what actually killed the process. The scripts are switched off now, each by its own option, so the crash reporter fires only on real crashes and stops filling `anki_miner.crash` with harmless dumps.
- **The kana exclusions skip the words they promise.** `ー` is filed in the katakana Unicode block, so a hiragana word carrying one — すごーい, ずーっと, きれー — counted as neither hiragana-only nor katakana-only and slipped past both switches; katakana stems with hiragana okurigana (サボる, ヤバい, ググる) matched neither either. Kana marks are script-neutral now, and ticking both boxes means a kanji-only deck, so the mixed-kana loanwords go too. Either box on its own still mines them.

### Removed
- **The word curator's video-preview switch**, along with the crash marker that turned it off by itself. The abort it guarded was a packaging fault — the Linux bundle's C++ runtime shadowing the host graphics driver — and that is fixed at the source, so the switch was a permanent setting standing in for a bug that no longer exists. `ANKI_MINER_NO_VIDEO_PREVIEW=1` still turns the preview off for anyone who needs it, and the notice on the pane names it.

## [2.9.2] - 2026-08-07

The accuracy release, with a crash fix in front of it. On some Linux systems the app died the moment a video mine reached the word curator — a GL driver failing to load inside the preview, which no traceback could survive. The preview is now optional, turns itself off after it kills the app, and the process death is recorded instead of vanishing. Behind that sits an audit of everything between raw subtitle text and the finished card: normalization, encoding, morphology, deinflection, compound and name matching, the filter chain, the reading formats, file pairing and the note-builder preflight. Around seventy fixes, most of them a class of word that was quietly getting the wrong front, reading, definition or sentence.

### Added
- **A switch for the word curator's video preview**, in Settings → Interface. Turning it off keeps the audio and the sentence — only the picture goes. `ANKI_MINER_NO_VIDEO_PREVIEW=1` does the same without touching settings, and the notice says so rather than pointing at a checkbox that will not help.
- **The preview turns itself off after it kills the app.** A marker is written before the video surface is built and cleared once it has drawn a frame; finding one at the next launch means the process died in between, so the preview is disabled and the screen says why, with a button to the setting.
- **Native crashes reach the log.** `SIGSEGV`/`SIGABRT` are routed to a dedicated `anki_miner.crash` file and folded into the log at the next start, so a log-only bug report now carries the native stack. The diagnostics snapshot gained the fields that name this class of cause: DRM driver and PCI ids, session type, the GL-relevant Qt environment, `LD_LIBRARY_PATH`, the bundled C++ runtime, the resolved libmpv, and the preview state.

### Changed
- **Yomitan zips with a wrong recorded CRC-32 now import** — dictionaries, frequency lists and pitch sources alike. Yomitan itself reads its own zips without checking CRCs, so archives published with bad checksums worked everywhere except here. Only a checksum mismatch falls back to an unverified read of that one member, and it is logged; truncated archives, bad headers and unsupported compression still fail. Integrity still comes from the JSON parse and the per-entry schema checks.

### Fixed
- **The word curator no longer takes the app down with it.** The GL surface is built at one gated site instead of unconditionally, the libmpv-absent path stops building a video widget just to draw a notice over it, and audio survives through a `vo=null` core, so the pane degrades rather than disappears.
- **The Linux bundle stopped shadowing the host graphics driver.** The bundle ships `libstdc++`/`libgcc_s` because Qt needs them, and the loader put them ahead of the system's — so a host newer than the build machine aborted inside its own Mesa driver. The launcher now preloads the host runtime when it is the newer of the two, with `ANKI_MINER_NO_CXX_SHIM=1` to opt out. The probe also failed to find `ldconfig` on Debian, where a non-root `PATH` has no `/sbin` — which had silently disabled the whole fix for `.deb` users.
- **Cards get the right word, reading and definition more often.** Unsafe lemma retries no longer attach a different homograph's data; a curated reading override now wins over the parser's and propagates to the sentence; the vowel-tail fold requires actual elongated-mora evidence; modern じる verbs keep a full-length highlight; the deinflection tail cap no longer truncates supported 14-character forms; compound classification stops assuming a nominal first token and inherits its part of speech only from content-word tails; name spans are matched before dictionary compounds, so an exact name still reaches the name-list filter; the dictionary character cap no longer prevents exact matches; and existence-cache eviction stops dropping hits the matcher still needs.
- **Subtitle text survives to the card intact.** Ordinary dialogue containing `<`, `>` or braces is no longer deleted as markup, HTML entities are decoded before tokenization instead of reaching the card encoded, literal `[` keeps its text, and emoji variation selectors are stripped with their emoji instead of surviving as stray characters. Encoding detection stops returning an empty parse when the cp932-first fallback misfires. A subtitle replaced without its mtime changing is re-parsed instead of replaying a stale token cache, and an ambiguous alternation can no longer slip past the regex-filter safety screen.
- **Filtering counts what you asked it to.** Reading-occurrence filtering now runs before sentence dedup rather than after it, and the offline-definition check moved ahead of every lossy sentence selector so a word with no definition can no longer erase the sentence a definable word needed. i+1 sentence selection no longer swaps in a line that would change the card front, and difficulty statistics stop collapsing distinct unknown fronts into one.
- **Reading sources survive malformed input.** Broken EPUBs raise the documented setup error instead of leaking a zip exception, the DRM gate identifies encrypted content rather than trusting a filename, the decompression cap applies to the whole book and not only per file, and `application/font-sfnt` counts as a font. Aozora headers survive leading blank lines and its explicit ruby markers now handle Latin-based bases. Sentence splitting handles halfwidth Japanese quotes and full stops, and CP932 halfwidth katakana is no longer decoded as unrelated EUC-JP. Mokuro sidecars are found regardless of filename case, uppercase `.ZIP` no longer defeats CBZ precedence, non-UTF-8 sidecars report properly, halfwidth-katakana-only blocks are classified correctly, and the count-only fallback no longer assigns an unrelated page.
- **Episode pairing picks the right file.** `Ep` no longer matches inside ordinary words such as "Steps", greedy seasonless matching stops discarding a complete two-segment match, the documented ASS-over-SSA-over-SRT precedence is honoured for folder pairing, a distinct file is no longer overwritten by Darwin-wide case folding, and subtitle ordering is total rather than partial.
- **The card-target preflight stops accepting a mapping that would break the card.** Field mappings that replace or bypass the mined expression are rejected, the active card-type marker is part of the collision check, and an AnkiConnect connection error propagates instead of being swallowed by the check.
- **Furigana distribution no longer stalls or gives up.** Backtracking over an ambiguous reading had exponential reachable work; it is now bounded, and nested ambiguous splits are resolved rather than discarded as failures.

### Fixed
- **Compound words read correctly.** Merged compounds used to build their kana by gluing together each piece's dictionary reading, which misses rendaku and junction changes — a 729-card audit found 20 cards shipping wrong readings (バカ力 as ばかりょく instead of ばかぢから, 体じゅう as たいじゅう instead of からだじゅう, Ｓ級 as Ｓきゅう instead of えすきゅう). When an installed offline dictionary attests the merged spelling, its reading now wins — on the Expression/Reading fields, the sentence furigana, and the audio/frequency lookup keys. Honorific kinship terms get the same treatment from a curated table: お兄ちゃん now reads おにいちゃん (not おあにちゃん), お父さん reads おとうさん — while forms like 兄上 (あにうえ) stay untouched. And when an inflected expression is mined (手っ取り早く → card front 手っ取り早い), the card's reading is the headword's attested one (てっとりばやい), not a re-tokenized concatenation.
- **Mined sentences no longer carry TV-caption decorations or redundant furigana.** Continuation arrows (➡ — present on 42% of audited broadcast-subtitle sentences), speaker/device emoji like 📱, replacement-character tofu, and private-use glyphs are stripped at tokenization, so they stay out of card sentences and word matching. Music note markers (♪) and quote brackets are deliberately kept — the regex filter presets own those. Separately, kana-only words no longer get pointless furigana brackets over themselves in the sentence field (バカ[ばか] renders as plain バカ), and stray spaces before plain-kana words are gone.
- **Frequency ranks are exact.** The blended sort rank computed across several frequency sources used floating-point math that truncated ~8% of single-source ranks to one below their true value (a card displaying rank 8219 sorted as 8218). The harmonic mean is now computed exactly, so the sort field always equals the displayed rank. Also, a CSV frequency source's display name no longer collapses to the literal word "source" after a reimport — cards show the source's real name again, and an already-mangled label is repaired on startup.
- **A folder name ending in a space no longer crashes batch mining.** The file selectors validated the real path but every consumer stripped trailing whitespace before touching the filesystem, so the stripped path didn't exist and the app aborted. Paths are now used exactly as validated, a vanished folder yields "no pairs" instead of a crash, and a new last-resort handler turns any similar unexpected error into a dialog + log entry instead of a silent core dump.
- **A 56-bug reliability sweep across the whole app.** The user-visible highlights: deck CSV export and card-deletion undo run off the GUI thread (no more multi-second freezes); Shift-JIS subtitle files load via a cp932 fallback instead of aborting the episode; failed queue items show a red error badge instead of vanishing silently; JMdict kanji headwords index **all** their readings, so more words find definitions; Google TTS synthesis is bounded by a timeout instead of hanging a run; desktop-shortcut creation quotes paths safely on Windows and Linux; and a timed-out worker no longer takes the whole app down when you re-run. The rest are hardening fixes in the queues, settings panels, dictionary import, and worker shutdown paths.
- **Mined cards no longer clip under Senren's colored dictionary rail.** The per-card glossary stylesheet used a `padding` shorthand on the dictionary-entry element that, by CSS specificity, also zeroed the left padding a Yomitan-aware note type puts there — on Senren with the Dictionary Colorizer enabled, the glossary text slid left under the colored bar (#93). The sheet now declares only top/bottom spacing on that element, so the note type's horizontal styling always wins; vertical spacing is unchanged. Existing cards pick the fix up via **Tools → Restyle Mined Cards**.
- **Kanji-variant spellings get their own definition and frequency.** A card for 殺る (やる, "to bump off") used to show 遣る's "to do" definition, and かける/掛ける/懸ける/賭ける all inherited the same frequency rank — the dictionary and frequency lookups queried UniDic's canonical headword instead of the spelling on the card. Lookups now query the card's spelling first and fall back to the canonical form only when no dictionary or frequency list knows the variant. Consequences: variant spellings now rank as themselves, so a rare spelling (賭ける) can drop below a "skip words ranked above N" cutoff it previously passed with 掛ける's rank — that's the fix working; the curation table's rank column and CSV export show the card-spelling's rank too. One narrow edge: with the Jisho online fallback enabled, a variant spelling found in no offline dictionary and known to Jisho only under its canonical form is now skipped (it appears in the "no definition" warning) instead of carded under the wrong headword.
